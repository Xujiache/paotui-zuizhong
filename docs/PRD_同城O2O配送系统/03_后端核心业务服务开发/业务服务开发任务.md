# 业务服务开发任务

> 版本: v1.1
> 状态: 基线版
> 所属阶段: 03_后端核心业务服务开发
> 后端框架: Express 4（中间件风格 `(req, res, next)`）
> 约定: 所有接口均需通过 tokenAuth() 中间件鉴权（除特殊标注外），响应格式遵循统一规范 { code, message, data }

---

## 全局约定

### 金额单位约定

> **所有金额字段在接口传输和数据库存储中统一使用"分"（整数）。**
> - 前端负责显示时除以 100 转为元（如 `amount / 100`）。
> - 后端接收和返回的金额字段值均为整数分，例如 `5800` 表示 `58.00 元`。
> - 此约定覆盖所有服务域：订单中心、计价中心、结算中心、售后中心等。

### Token Key 格式约定

> Token 在 Redis 中的存储 Key 统一包含角色信息：
> - Access Token Key: `token:access:{role}:{userId}`，TTL 2小时
> - Refresh Token Key: `token:refresh:{role}:{userId}`，TTL 7天
> - 其中 `{role}` 取值为 `USER` / `MERCHANT` / `RIDER` / `ADMIN`

### 核心接口详细定义

**M-14 获取附近商家**

请求参数（Query）：
```
lat=22.5431          // 用户纬度（必填）
lng=113.9472         // 用户经度（必填）
distance=3000        // 搜索范围(米)，默认3000
category=            // 类目筛选
keyword=             // 关键词搜索

```

业务规则：
- 只返回状态为OPEN且审核通过的门店
- 按距离计算排序（使用 Haversine 公式或数据库地理函数）
- 返回门店距离、预计配送时间、起送价、配送费、营业状态

返回值（列表项）：
```json
{
  "id": 1,

  "logo": "...",
  "category": "快餐便当",
  "distance": 1200,
  "deliveryTime": 30,
  "minOrderAmount": 15.00,
  "deliveryFee": 3.00,
  "rating": 4.8,
  "monthlySales": 520,
  "status": "OPEN",
  "tags": ["满20减5"]

```

**M-10 商家审核**

请求体：
```json
{
  "action": "APPROVE",
  "remark": "资料齐全，审核通过"
}
```

action: APPROVE通过 / REJECT驳回

业务规则：
- 仅 audit_status=PENDING 的商家可审核
- 审核通过：audit_status → APPROVED, status → ACTIVE
- 审核驳回：audit_status → REJECTED, status → REJECTED
- 记录审计日志
- 发送审核结果通知（消息中心）

幂等要求：重复审核同一商家，如已非PENDING状态则返回错误

- 库存不能为负数
- DECREMENT时如果库存不足返回错误 (15001)
- 库存变更需要考虑并发安全（MySQL乐观锁或 `UPDATE ... SET stock = stock - ? WHERE stock >= ?`）

### 核心计算逻辑

**PR-01 商品订单计价**

输入参数：
```json
{
  "storeId": 1,
  "items": [{ "skuId": 101, "quantity": 2, "price": 25.00 }],
  "deliveryLat": 22.5431,
  "deliveryLng": 113.9472,
  "couponRecordId": null
}
```

计算过程：
1. 商品金额 = Σ(每项 price × quantity)
2. 打包费 = Σ(每项商品的packingFee × quantity) 或按门店固定打包费
3. 配送费 = 根据门店配置和距离计算
4. 时段加价 = 匹配当前时段的加价规则
5. 天气加价 = 匹配当前天气的加价规则（首期可简化，由后台手动配置）
6. 优惠券抵扣 = 匹配并计算优惠券减免
7. 总金额 = 商品金额 + 打包费 + 配送费 + 时段加价 + 天气加价 - 优惠券抵扣
8. 实付金额 = MAX(总金额, 最小支付金额0.01)

返回值：
```json
{
  "productAmount": 50.00,
  "packingFee": 4.00,
  "deliveryFee": 5.00,
  "extraFee": 2.00,
  "discountAmount": 3.00,
  "totalAmount": 58.00,
  "paidAmount": 58.00,
  "feeDetails": [
    { "name": "商品金额", "amount": 50.00 },
    { "name": "打包费", "amount": 4.00 },
    { "name": "配送费", "amount": 5.00 },
    { "name": "高峰时段加价", "amount": 2.00 },
    { "name": "优惠券", "amount": -3.00 }
  ]
}
```

**PR-02 跑腿订单计价**

计算公式：
```
总金额 = 基础服务费 + 距离费 + 重量费 + 楼层费 + 时段加价 + 天气加价 + 小费 + 代买垫付
```

按服务类型匹配对应的 pricing_rules 记录，依次计算每项费用。

- 冻结相关结算
- 通知商家/骑手/客服

### 核心逻辑

**S-01 触发结算**

订单完成后自动触发，计算分账：

商品订单：
- 商家收入 = 订单实付金额 - 平台佣金 - 配送费
- 平台佣金 = 订单实付金额 × 门店佣金比例
- 骑手收入 = 配送费

跑腿订单：
- 骑手收入 = 订单实付金额 - 平台服务费 + 小费
- 平台服务费 = 按规则计算

生成两条 settlements 记录（商家一条、骑手一条），更新余额。

**S-06 申请提现**

请求体：
```json
{
  "amount": 500.00,
  "accountType": "WECHAT",
  "accountName": "张三",
  "accountNo": ""
}
```

业务规则：
- 提现金额不超过可用余额
- 最小提现金额由配置中心控制（默认1元）
- 每天提现次数限制（默认3次）
- 创建提现记录 status=PENDING
- 冻结对应金额（balance减少，frozen_balance增加）
- 通知平台管理员审核

### 消息发送流程

MSG-01 为内部调用接口，其他服务通过调用消息中心发送通知：

```typescript
await messageService.send({
  targetType: 'USER',
  targetId: userId,
  type: 'ORDER',
  title: '订单已接单',
  content: '您的订单已被商家接单，正在备货中',
  extra: { orderId: 1001, action: 'MERCHANT_ACCEPT' },
  channels: ['INTERNAL', 'WX_SUBSCRIBE', 'APP_PUSH'],
});
```

多通道分发逻辑：
- INTERNAL：写入 messages 表
- WX_SUBSCRIBE：调用微信订阅消息 API
- APP_PUSH：调用推送服务（极光/个推）
- SMS：调用短信服务

降级策略：推送失败 → 记录失败日志 → 确保站内消息已写入
