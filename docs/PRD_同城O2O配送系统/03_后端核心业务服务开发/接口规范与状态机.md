## 一、统一接口响应格式

### 1.1 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

### 1.2 分页响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 100,
      "totalPages": 5
    }
  }
}
```

### 1.3 错误响应

```json
{
  "code": 10001,
  "message": "参数校验失败",
  "data": null,
  "errors": [
    { "field": "phone", "message": "手机号格式不正确" }
  ]
}
```

## 三、商品订单状态机

### 3.1 状态定义

| 状态码 | 状态名 | 说明 | 终态 |
|--------|--------|------|------|
| PENDING_PAYMENT | 待支付 | 用户已提交订单，等待支付 | 否 |
| CLOSED_UNPAID | 已关闭(未支付) | 支付超时自动关闭 | 是 |
| PENDING_MERCHANT | 待商家接单 | 支付成功，等待商家处理 | 否 |
| MERCHANT_REJECTED | 商家拒单 | 商家主动拒绝订单 | 是(触发退款) |
| MERCHANT_TIMEOUT | 商家超时 | 商家超时未接单 | 是(触发退款) |
| PENDING_RIDER | 待骑手接单 | 商家已接单，等待骑手抢单 | 否 |
| CANCELLED | 已取消 | 用户在商家/骑手接单前主动取消 | 否(等待退款) |
| PENDING_PICKUP | 待取货 | 骑手已接单，等待到店取货 | 否 |
| DELIVERING | 配送中 | 骑手已取货，配送中 | 否 |
| DELIVERED | 已送达 | 骑手确认送达 | 否 |
| COMPLETED | 已完成 | 用户确认收货或系统自动确认 | 是 |
| AFTERSALE | 售后处理中 | 退款/投诉介入中 | 否 |
| REFUNDED | 已退款 | 退款完成 | 是 |

### 3.2 状态转换矩阵

```mermaid
stateDiagram-v2
    [*] --> PENDING_PAYMENT: 用户提交订单

    PENDING_PAYMENT --> CLOSED_UNPAID: 支付超时(15分钟)\n触发: 定时任务\n前置: 无\n后置: 释放库存预扣
    PENDING_PAYMENT --> PENDING_MERCHANT: 支付成功\n触发: 支付回调\n前置: 金额一致性校验\n后置: 通知商家

    PENDING_MERCHANT --> MERCHANT_REJECTED: 商家拒单\n触发: 商家操作\n前置: 无\n后置: 自动退款+通知用户
    PENDING_MERCHANT --> MERCHANT_TIMEOUT: 商家超时未接(5分钟)\n触发: 定时任务\n前置: 无\n后置: 自动退款+通知用户
    PENDING_MERCHANT --> PENDING_RIDER: 商家接单\n触发: 商家操作\n前置: 门店营业中\n后置: 订单入骑手池+通知用户
    PENDING_MERCHANT --> CANCELLED: 用户主动取消\n触发: 用户操作\n前置: 无\n后置: 释放库存+发起退款

    PENDING_RIDER --> PENDING_PICKUP: 骑手抢单\n触发: 骑手操作\n前置: 骑手在线+审核通过\n后置: 从订单池移除+通知用户和商家
    PENDING_RIDER --> CANCELLED: 用户主动取消\n触发: 用户操作\n前置: 平台规则判定\n后置: 从订单池移除+发起退款

    CANCELLED --> REFUNDED: 退款完成\n触发: 系统(微信退款回调)\n前置: 退款已发起\n后置: 更新支付状态

    PENDING_PICKUP --> DELIVERING: 骑手确认取货\n触发: 骑手操作\n前置: 已到店\n后置: 通知用户
    PENDING_PICKUP --> AFTERSALE: 售后介入\n触发: 用户/客服\n前置: 无\n后置: 冻结结算

    DELIVERING --> DELIVERED: 骑手确认送达\n触发: 骑手操作\n前置: 拍照/签收(可选)\n后置: 通知用户
    DELIVERING --> AFTERSALE: 售后介入\n触发: 用户/客服/骑手异常上报\n前置: 无\n后置: 冻结结算

    DELIVERED --> COMPLETED: 用户确认收货/自动确认(24小时)\n触发: 用户操作/定时任务\n前置: 无\n后置: 触发结算+开放评价
    DELIVERED --> AFTERSALE: 售后申请\n触发: 用户操作\n前置: 无\n后置: 冻结结算

    AFTERSALE --> REFUNDED: 退款完成\n触发: 系统\n前置: 退款审核通过\n后置: 执行微信退款+回滚结算
    AFTERSALE --> COMPLETED: 售后关闭(驳回)\n触发: 平台操作\n前置: 审核判定\n后置: 解冻结算

    CLOSED_UNPAID --> [*]
    MERCHANT_REJECTED --> [*]
    MERCHANT_TIMEOUT --> [*]
    CANCELLED --> [*]
    COMPLETED --> [*]
    REFUNDED --> [*]
```

### 3.3 每个状态转换的详细定义

| 转换 | 从状态 | 到状态 | 触发者 | 前置校验 | 后置动作 |
|------|--------|--------|--------|----------|----------|
| 支付超时 | PENDING_PAYMENT | CLOSED_UNPAID | SYSTEM | 当前时间 > pay_deadline | 释放库存预扣；写操作日志 |
| 支付成功 | PENDING_PAYMENT | PENDING_MERCHANT | SYSTEM | 支付回调验签通过；金额一致 | 更新支付记录；通知商家（推送+语音）；写日志 |
| 商家接单 | PENDING_MERCHANT | PENDING_RIDER | MERCHANT | 门店营业中；操作者属于该门店 | 记录接单时间；订单入骑手池；通知用户 |
| 商家拒单 | PENDING_MERCHANT | MERCHANT_REJECTED | MERCHANT | 操作者属于该门店 | 发起自动退款；通知用户；释放库存 |
| 商家超时 | PENDING_MERCHANT | MERCHANT_TIMEOUT | SYSTEM | 接单超过5分钟（可配置） | 发起自动退款；通知用户；释放库存 |
| 用户取消(商家未接) | PENDING_MERCHANT | CANCELLED | USER | 订单属于该用户 | 释放库存；发起自动退款 |
| 用户取消(骑手未接) | PENDING_RIDER | CANCELLED | USER | 平台规则判定 | 从订单池移除；发起自动退款 |
| 退款完成(已取消) | CANCELLED | REFUNDED | SYSTEM | 退款回调确认 | 更新支付状态；写操作日志 |
| 骑手抢单 | PENDING_RIDER | PENDING_PICKUP | RIDER | 骑手在线；审核通过；分布式锁 | 绑定骑手；从池中移除；通知用户和商家 |
| 骑手取货 | PENDING_PICKUP | DELIVERING | RIDER | 骑手已到店（可选校验） | 记录取货时间；通知用户 |
| 骑手送达 | DELIVERING | DELIVERED | RIDER | 可附带拍照/签收证明 | 记录送达时间；通知用户确认 |
| 用户确认 | DELIVERED | COMPLETED | USER/SYSTEM | 用户主动确认或送达后24小时自动 | 记录完成时间；触发结算；开放评价 |
| 售后介入 | 多状态 | AFTERSALE | USER/ADMIN | 无进行中售后 | 冻结结算；创建售后记录 |
| 退款完成 | AFTERSALE | REFUNDED | SYSTEM | 退款审核通过 | 执行微信退款；回滚结算 |
| 售后关闭 | AFTERSALE | COMPLETED | ADMIN | 审核判定售后不成立 | 解冻结算；通知用户 |

## 四、跑腿订单状态机

### 4.1 状态定义

| 状态码 | 状态名 | 说明 | 终态 |
|--------|--------|------|------|
| PENDING_PAYMENT | 待支付 | 等待支付 | 否 |
| CLOSED_UNPAID | 已关闭(未支付) | 支付超时 | 是 |
| PENDING_REVIEW | 待审核 | 代办类需平台审核 | 否 |
| PENDING_DISPATCH | 待接单 | 等待骑手抢单 | 否 |
| CANCELLED | 已取消 | 用户取消(骑手未接) | 是 |
| RIDER_ACCEPTED | 骑手已接单 | 骑手抢单成功 | 否 |
| ON_THE_WAY | 前往取件 | 骑手出发前往取件点 | 否 |
| IN_PROGRESS | 服务进行中 | 骑手执行任务 | 否 |
| DELIVERED | 任务已送达 | 骑手完成交付 | 否 |
| COMPLETED | 已完成 | 用户确认完成 | 是 |
| AFTERSALE | 售后处理中 | 售后介入 | 否 |
| REFUNDED | 已退款 | 退款完成 | 是 |

### 4.2 状态转换矩阵

```mermaid
stateDiagram-v2
    [*] --> PENDING_PAYMENT: 用户提交跑腿订单

    PENDING_PAYMENT --> CLOSED_UNPAID: 支付超时(15分钟)
    PENDING_PAYMENT --> PENDING_REVIEW: 支付成功(需审核类)\n如代办/特殊帮买
    PENDING_PAYMENT --> PENDING_DISPATCH: 支付成功(免审核类)\n帮送/帮取/普通帮买

    PENDING_REVIEW --> PENDING_DISPATCH: 审核通过\n后置:订单入骑手池
    PENDING_REVIEW --> REFUNDED: 审核驳回\n后置:自动退款

    PENDING_DISPATCH --> CANCELLED: 用户取消\n后置:自动退款
    PENDING_DISPATCH --> RIDER_ACCEPTED: 骑手抢单\n前置:骑手在线+审核通过

    RIDER_ACCEPTED --> ON_THE_WAY: 骑手出发\n触发:骑手操作
    RIDER_ACCEPTED --> AFTERSALE: 售后介入

    ON_THE_WAY --> IN_PROGRESS: 骑手到达并开始执行\n(帮买:开始购买)(帮取:开始取件)
    ON_THE_WAY --> AFTERSALE: 售后介入

    IN_PROGRESS --> DELIVERED: 任务完成送达\n触发:骑手确认送达
    IN_PROGRESS --> AFTERSALE: 售后介入

    DELIVERED --> COMPLETED: 用户确认/自动确认(24小时)\n后置:触发结算
    DELIVERED --> AFTERSALE: 售后申请

    AFTERSALE --> REFUNDED: 退款完成
    AFTERSALE --> COMPLETED: 售后关闭

    CLOSED_UNPAID --> [*]
    CANCELLED --> [*]
    COMPLETED --> [*]
    REFUNDED --> [*]
```

### 4.3 跑腿订单特殊规则

| 服务类型 | 是否需审核 | 特殊流程 |
|----------|-----------|----------|
| 帮送(DELIVER) | 否 | 标准流程 |
| 帮取(PICKUP) | 否 | 需要取件码验证 |
| 帮买(BUY) | 否(可配置) | 涉及垫付：骑手购买后上传小票，差价由平台处理 |
| 代办(ERRAND) | 是(可配置) | 后台审核通过后入池 |

帮买垫付流程：
1. 用户下单时填写预算金额
2. 骑手按预算购买，实际金额可能有差异
3. 骑手在APP中填写实际购买金额并上传小票
4. 如实际 < 预算：差额退还用户
5. 如实际 > 预算：发起补差价通知，用户确认后追加支付
6. 具体垫付规则由后台配置（首期建议固定预算，不支持超预算）

## 五、售后状态机

```mermaid
stateDiagram-v2
    [*] --> PENDING_ACCEPT: 用户提交售后申请

    PENDING_ACCEPT --> PROCESSING: 受理\n触发:商家/客服
    PENDING_ACCEPT --> PENDING_REFUND: 自动审核通过(特定条件)\n如商家未接单阶段的取消

    PROCESSING --> PENDING_REFUND: 同意退款\n触发:商家/客服
    PROCESSING --> REJECTED: 驳回申请\n触发:商家/客服

    PENDING_REFUND --> REFUNDED: 退款到账\n触发:系统(微信退款回调)
    PENDING_REFUND --> PROCESSING: 退款失败需重试\n触发:系统

    REJECTED --> CLOSED: 用户接受驳回/超时关闭

    REFUNDED --> CLOSED: 售后完结
    CLOSED --> [*]
```

| 转换 | 触发者 | 前置校验 | 后置动作 |
|------|--------|----------|----------|
| 提交 → PENDING_ACCEPT | USER | 无进行中售后；退款金额合法 | 订单状态 → AFTERSALE；冻结结算 |
| 受理 → PROCESSING | MERCHANT/ADMIN | 售后状态为PENDING_ACCEPT | 通知用户处理中 |
| 同意 → PENDING_REFUND | MERCHANT/ADMIN | 售后状态为PROCESSING | 触发退款执行；通知用户 |
| 自动通过 → PENDING_REFUND | SYSTEM | 满足自动退款条件 | 触发退款执行 |
| 退款成功 → REFUNDED | SYSTEM | 微信退款回调成功 | 订单状态 → REFUNDED；回滚结算 |
| 驳回 → REJECTED | MERCHANT/ADMIN | 售后状态为PROCESSING | 通知用户；解冻结算 |

## 六、支付状态机

```mermaid
stateDiagram-v2
    [*] --> UNPAID: 创建支付记录

    UNPAID --> PAYING: 发起支付\n(调用微信统一下单)
    UNPAID --> UNPAID: 支付超时重新发起

    PAYING --> PAID: 支付成功\n(支付回调确认)
    PAYING --> PAY_FAILED: 支付失败
    PAYING --> UNPAID: 支付取消

    PAY_FAILED --> PAYING: 重新支付

    PAID --> REFUNDING: 发起退款
    PAID --> PARTIAL_REFUNDED: 部分退款到账
    PAID --> FULL_REFUNDED: 全额退款到账

    REFUNDING --> PARTIAL_REFUNDED: 部分退款成功
    REFUNDING --> FULL_REFUNDED: 全额退款成功

    PARTIAL_REFUNDED --> REFUNDING: 继续退款
    PARTIAL_REFUNDED --> FULL_REFUNDED: 剩余退款完成
```

### 7.3 退款流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant GW as API网关
    participant ASC as 售后中心
    participant OS as 订单中心
    participant SC as 结算中心
    participant PAY as 微信支付
    participant MS as 消息中心

    U->>GW: POST /aftersale/refund (订单+原因+金额)
    GW->>ASC: 创建退款申请
    ASC->>OS: 获取订单信息,校验状态
    ASC->>ASC: 创建售后记录(PENDING_ACCEPT)
    ASC->>OS: 订单状态→AFTERSALE
    ASC->>SC: 冻结相关结算
    ASC->>MS: 通知商家/客服

    alt 自动审核(商家未接单阶段)
        ASC->>ASC: 自动通过(PENDING_REFUND)
        ASC->>PAY: 调用微信退款API
        PAY-->>ASC: 退款回调
        ASC->>ASC: 状态→REFUNDED
        ASC->>OS: 订单状态→REFUNDED
        ASC->>SC: 回滚结算
        ASC->>MS: 通知用户退款到账
    else 人工审核
        Note over ASC: 客服/商家处理
        ASC->>ASC: 受理(PROCESSING)
        alt 同意退款
            ASC->>ASC: 状态→PENDING_REFUND
            ASC->>PAY: 调用微信退款API
            PAY-->>ASC: 退款回调
            ASC->>ASC: 状态→REFUNDED
            ASC->>OS: 订单状态→REFUNDED
            ASC->>SC: 回滚结算
            ASC->>MS: 通知用户退款到账
        else 驳回
            ASC->>ASC: 状态→REJECTED
            ASC->>OS: 订单状态恢复
            ASC->>SC: 解冻结算
            ASC->>MS: 通知用户驳回
        end
    end
```

### 7.4 结算流程

```mermaid
sequenceDiagram
    participant OS as 订单中心
    participant SC as 结算中心
    participant DB as MySQL
    participant MS as 消息中心

    OS->>SC: 订单完成,触发结算(orderId)
    SC->>OS: 获取订单详情(金额,类型,门店佣金率)
    
    alt 商品订单
        SC->>SC: 计算商家收入 = 实付 - 佣金 - 配送费
        SC->>SC: 计算平台佣金 = 实付 × 佣金率
        SC->>SC: 计算骑手收入 = 配送费
        SC->>DB: 创建商家结算记录
        SC->>DB: 创建骑手结算记录
        SC->>DB: 更新商家余额(merchants.balance)
        SC->>DB: 更新骑手余额(riders.balance)
    else 跑腿订单
        SC->>SC: 计算骑手收入 = 实付 - 平台服务费 + 小费
        SC->>SC: 计算平台收入 = 平台服务费
        SC->>DB: 创建骑手结算记录
        SC->>DB: 更新骑手余额
    end

    SC->>DB: 更新订单 settlement_status = SETTLED
    SC->>MS: 通知商家/骑手结算完成
```

## 八、幂等要求汇总

| 接口 | 幂等策略 | 幂等Key |
|------|----------|---------|
| 支付回调 | 基于支付单号去重 | `idempotent:payment:{paymentNo}` |
| 创建商品订单 | 基于用户+门店+商品+时间窗口 | `idempotent:order:{userId}:{storeId}:{hash}` |
| 创建跑腿订单 | 基于用户+服务类型+地址+时间窗口 | `idempotent:errand:{userId}:{serviceType}:{hash}` |
| 骑手抢单 | 分布式锁 + 状态二次检查 | `dispatch:lock:{orderId}` |
| 商家接单/拒单 | 状态前置检查 | 数据库状态字段 |
| 退款执行 | 基于售后单号去重 | `idempotent:refund:{aftersaleNo}` |
| 退款回调 | 基于退款交易号去重 | `idempotent:refund_cb:{transactionId}` |
