### 1.4 数据库初始化

```bash
# 连接 MySQL 创建数据库
mysql -u root -p

# 执行以下 SQL

CREATE DATABASE o2o_delivery_test DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

GRANT ALL PRIVILEGES ON o2o_delivery_test.* TO 'o2o_dev'@'localhost';
```

### 1.5 项目启动步骤

```bash

# 3. 管理后台启动

npm install

# 5. 商家APP / 骑手APP（在 HBuilderX 中打开）
# 在 HBuilderX 中导入 merchant-app / rider-app 目录
# 运行到模拟器或真机
```

## 三、代码规范

### 3.1 命名规范

#### 文件命名

| 类型 | 规则 | 示例 |
|------|------|------|
| TypeScript 文件 | camelCase | `orderService.ts`, `authMiddleware.ts` |
| Vue 组件文件（管理后台） | PascalCase | `OrderList.vue`, `UserProfile.vue` |
| uni-app x 页面/组件文件 | PascalCase | `OrderList.uvue`, `UserProfile.uvue`（.uvue格式，UTS语言） |
| 样式文件 | kebab-case | `order-list.scss`, `common-style.css` |
| 常量/配置文件 | camelCase | `constants.ts`, `database.ts` |
| 类型定义文件 | camelCase + `.d.ts` | `request.d.ts`, `enums.ts` |
| 测试文件 | 源文件名 + `.test.ts` | `orderService.test.ts` |
| 路由文件 | 模块名 + `.routes.ts` | `order.routes.ts` |
| 模型文件 | 模块名 + `.model.ts` | `order.model.ts` |

#### 变量命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 变量 | camelCase | `orderList`, `totalAmount` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT`, `DEFAULT_PAGE_SIZE` |
| 函数 | camelCase，动词开头 | `getOrderById()`, `createUser()` |
| 类 | PascalCase | `OrderService`, `UserModel` |
| 接口/类型 | PascalCase, I前缀可选 | `CreateOrderDTO`, `UserInfo` |
| 枚举 | PascalCase，成员UPPER_SNAKE | `OrderStatus.PENDING_PAYMENT` |
| 布尔变量 | is/has/can 前缀 | `isActive`, `hasPermission` |
| 私有成员 | 下划线前缀或 `#private` | `_connection`, `#cache` |

### 3.2 TypeScript 编码规范

- 所有变量和函数必须显式声明类型，禁止使用 `any`（极少数不可避免场景除外）
- 使用 `interface` 定义对象结构，使用 `type` 定义联合类型和工具类型
- 优先使用 `const` 声明变量，需要重新赋值时使用 `let`，禁止使用 `var`
- 异步操作统一使用 `async/await`，禁止 callback 嵌套
- 函数参数超过3个时使用对象参数
- 所有导出的函数和类必须有 JSDoc 注释说明用途

### 3.3 Vue / uni-app x 编码规范

- 管理后台（.vue）：使用 `<script setup lang="ts">` 语法
- uni-app x移动端（.uvue）：使用 `<script lang="uts">` 语法（UTS语言）
- 组件 Props 必须使用类型接口定义
- 组件命名使用 PascalCase，模板中使用 kebab-case
- 优先使用组合式函数（composables）抽取可复用逻辑
- 响应式数据使用 `ref` / `reactive`，计算属性使用 `computed`

### 3.4 Git 提交规范

采用 Conventional Commits 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

| type | 说明 | 示例 |
|------|------|------|
| feat | 新功能 | `feat(order): 添加商品订单创建接口` |
| fix | 修复Bug | `fix(auth): 修复Token过期后无法刷新的问题` |
| docs | 文档 | `docs: 更新API接口文档` |
| style | 代码格式 | `style: 统一缩进为2空格` |
| refactor | 重构 | `refactor(user): 重构用户地址服务` |
| test | 测试 | `test(order): 添加订单创建单元测试` |
| chore | 构建/工具 | `chore: 升级TypeScript到5.3` |
| perf | 性能优化 | `perf(product): 优化商品列表查询性能` |

scope 使用服务域名称：auth, user, merchant, rider, product, order, pricing, dispatch, aftersale, settlement, message, config, risk, admin, gateway

## 四、Git 分支管理策略

### 4.1 分支模型

```mermaid
gitgraph
    commit id: "init"
    branch develop
    checkout develop
    commit id: "base setup"
    branch feature/auth
    checkout feature/auth
    commit id: "auth service"
    commit id: "auth test"
    checkout develop
    merge feature/auth
    branch feature/order
    checkout feature/order
    commit id: "order service"
    checkout develop
    merge feature/order
    branch release/v1.0
    checkout release/v1.0
    commit id: "version bump"
    checkout main
    merge release/v1.0 tag: "v1.0.0"
```

### 4.2 分支定义

| 分支 | 用途 | 来源 | 合并目标 | 命名规则 |
|------|------|------|----------|----------|
| main | 生产分支，仅包含已发布代码 | release | - | `main` |
| develop | 开发主干，日常集成 | main | release | `develop` |
| feature/* | 功能分支 | develop | develop | `feature/模块-功能描述` |
| bugfix/* | Bug修复分支 | develop | develop | `bugfix/问题描述` |
| release/* | 发布分支 | develop | main + develop | `release/v版本号` |
| hotfix/* | 紧急修复 | main | main + develop | `hotfix/问题描述` |

### 4.3 分支操作规范

- 每个功能对应一个 feature 分支，从 develop 拉取
- feature 分支开发完成后通过 Pull Request 合并回 develop
- PR 必须经过至少1人 Code Review 后方可合并
- 合并时使用 Squash Merge 保持提交历史整洁
- 禁止直接向 main 和 develop 分支 push
- 发布前从 develop 拉取 release 分支做最终测试

## 五、API 接口规范

### 5.1 URL 命名规范

```
{baseUrl}/api/v1/{service}/{resource}
```

| 规则 | 说明 | 示例 |
|------|------|------|
| 使用 REST 风格 | 资源名词复数 | `/api/v1/orders` |
| 版本号 | URL中包含版本号 | `/api/v1/...` |
| 按服务域分组 | 服务域作为路径前缀 | `/api/v1/user/addresses` |
| 小写+连字符 | URL路径使用小写和连字符 | `/api/v1/order/order-items` |
| 操作动词用HTTP方法 | 不在URL中使用动词 | `POST /api/v1/orders`（不用 `/api/v1/orders/create`） |

特殊操作使用动词路径：

| 操作 | 示例 |
|------|------|
| 登录 | `POST /api/v1/auth/login` |
| 登出 | `POST /api/v1/auth/logout` |
| 刷新Token | `POST /api/v1/auth/refresh-token` |
| 订单抢单 | `POST /api/v1/dispatch/orders/:id/grab` |
| 订单取消 | `POST /api/v1/orders/:id/cancel` |

各服务域路由前缀：

## 六、数据库命名规范

### 6.1 表命名

| 规则 | 说明 | 示例 |
|------|------|------|
| 小写 + 下划线 | snake_case | `order_items`, `user_addresses` |
| 名词复数 | 表名使用复数形式 | `orders`, `users`, `products` |
| 不加表前缀 | 不使用 `t_`、`tbl_` 等前缀 | `orders`（不用 `t_orders`） |
| 关联表 | 两个表名组合 | `role_permissions` |

### 6.2 字段命名

| 规则 | 说明 | 示例 |
|------|------|------|
| 小写 + 下划线 | snake_case | `order_no`, `created_at` |
| 主键 | 统一使用 `id` | `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 外键 | 关联表名单数 + `_id` | `user_id`, `store_id`, `order_id` |
| 时间字段 | `*_at` 后缀 | `created_at`, `updated_at`, `paid_at` |
| 状态字段 | `status` 或 `*_status` | `status`, `payment_status`, `audit_status` |
| 布尔字段 | `is_*` 前缀 | `is_default`, `is_active`, `is_deleted` |
| 金额字段 | DECIMAL(10,2) | `total_amount`, `paid_amount` |
| JSON字段 | 使用 JSON 类型 | `spec_values JSON` |

### 6.3 索引命名

| 索引类型 | 命名规则 | 示例 |
|----------|----------|------|
| 主键 | `pk_{表名}` (自动) | `pk_orders` |
| 唯一索引 | `uk_{表名}_{字段}` | `uk_users_phone` |
| 普通索引 | `idx_{表名}_{字段}` | `idx_orders_user_id` |
| 组合索引 | `idx_{表名}_{字段1}_{字段2}` | `idx_orders_store_id_status` |

### 6.4 通用字段

每张表必须包含以下通用字段：

```sql
id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
is_deleted  TINYINT(1) NOT NULL DEFAULT 0
```

- `id`：自增主键（BIGINT保证容量）
- `created_at`：创建时间
- `updated_at`：最后更新时间
- `is_deleted`：软删除标记（0未删除/1已删除）
