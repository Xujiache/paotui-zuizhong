# 平台管理后台 - 功能模块开发任务

> 版本: v1.0
> 状态: 基线版
> 适用终端: 平台管理后台（PC端）
> 技术栈: Vue 3.5 + Vite 7 + Element Plus 2.11 + Tailwind CSS 4 + Pinia 3 + TypeScript 5.6（基于 art-design-pro 模板）

本文档定义平台管理后台全部24个菜单页面的详细开发规格。每个页面包含页面目标、布局、字段定义、操作与权限、依赖接口、业务规则和验收要点。

---

## 通用约定

### 页面布局规范

所有列表型页面统一采用以下布局：
```
┌──────────────────────────────────────┐
│ 面包屑导航                            │
├──────────────────────────────────────┤
│ 搜索区（El-Form inline模式）           │
│ [搜索条件1] [搜索条件2] [查询] [重置]   │
├──────────────────────────────────────┤
│ 操作区                                │
│ [新增] [批量操作] [导出]               │
├──────────────────────────────────────┤
│ 列表区（El-Table）                     │
│ □ | 序号 | 字段1 | 字段2 | ... | 操作  │
│   |  1   | xxx   | xxx   | ... | 操作  │
├──────────────────────────────────────┤
│ 分页区（El-Pagination）               │
│ 共X条 | 每页X条 | < 1 2 3 > |          │
└──────────────────────────────────────┘
```

### 通用字段约定

| 约定 | 说明 |
|------|------|
| 分页 | 默认每页20条，可选10/20/50/100 |
| 时间格式 | `YYYY-MM-DD HH:mm:ss` |
| 金额格式 | 精确到分，展示时保留2位小数，单位"元" |
| 状态展示 | 使用 El-Tag，不同状态不同颜色 |
| 操作列 | 固定在右侧，宽度自适应 |
| 空数据 | 使用 El-Empty 组件展示 |
| 加载状态 | 列表/详情均需 loading 状态 |

### 通用接口约定

| 约定 | 说明 |
|------|------|
| 请求基路径 | `/api/admin/v1` |
| 认证方式 | Header携带 `Authorization: Bearer {token}` |
| 请求格式 | JSON (`Content-Type: application/json`) |
| 统一响应格式 | `{ code: number, message: string, data: any }` |
| 分页参数 | `page`(页码,从1开始), `pageSize`(每页条数) |
| 分页响应 | `{ list: [], total: number, page: number, pageSize: number }` |

## AD-01 数据看板

### 基本信息

| 属性 | 值 |
|------|-----|
| 页面编号 | AD-01 |
| 页面名称 | 数据看板 |
| 所属菜单 | 一级菜单：首页 |
| 可访问角色 | 超级管理员、运营人员、财务人员 |
| 优先级 | P0 |
| 路由路径 | `/dashboard` |

### 页面目标

为平台管理者提供实时运营数据概览，包括订单趋势、交易数据、用户和骑手活跃情况，辅助运营决策。

### 页面布局

```
┌────────────────────────────────────────────────┐
│ 顶部统计卡片区（4个卡片横排）                      │
│ [今日订单数] [今日交易额] [活跃用户数] [在线骑手数]  │
├──────────────────┬─────────────────────────────┤
│ 订单趋势图       │ 订单类型占比饼图               │
│ (折线图,7/30天)  │ (商品单/跑腿单)               │
├──────────────────┴─────────────────────────────┤
│ 关键指标看板区（6个小卡片）                        │
│ [完成率][取消率][平均配送时长][商家接单率]           │
│ [骑手抢单率][售后率]                              │
├──────────────────┬─────────────────────────────┤
│ 待处理事项列表    │ 实时订单状态分布               │
│ (待审核/待处理)  │ (柱状图)                      │
└──────────────────┴─────────────────────────────┘
```

### 数据卡片定义

| 卡片名称 | 数据来源 | 展示格式 | 对比说明 |
|----------|----------|----------|----------|
| 今日订单数 | 订单中心 | 整数 | 较昨日同期 ↑/↓ 百分比 |
| 今日交易额 | 结算中心 | ¥xxx.xx | 较昨日同期 ↑/↓ 百分比 |
| 活跃用户数 | 用户中心 | 整数 | 较昨日同期 ↑/↓ 百分比 |
| 在线骑手数 | 骑手中心 | 整数(在线/总数) | 实时数据 |

### 图表定义

| 图表 | 类型 | X轴 | Y轴/数据 | 交互 |
|------|------|-----|----------|------|
| 订单趋势图 | 折线图(ECharts 6) | 日期 | 订单量/交易额 双Y轴 | 支持7天/30天切换 |
| 订单类型占比 | 饼图(ECharts 6) | - | 商品订单/帮送/帮取/帮买/代办 | hover显示数量和占比 |
| 订单状态分布 | 柱状图(ECharts 6) | 状态名 | 订单数量 | 实时刷新 |

### 待处理事项

| 事项 | 数据来源 | 点击行为 |
|------|----------|----------|
| 待审核商家 | 商家中心 | 跳转 AD-03 |
| 待审核骑手 | 骑手中心 | 跳转 AD-04 |
| 待处理退款 | 售后中心 | 跳转 AD-09 |
| 待处理投诉 | 售后中心 | 跳转 AD-10 |
| 待审核提现 | 结算中心 | 跳转 AD-18 |
| 异常订单 | 订单中心 | 跳转 AD-08 |

### 依赖后端接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取统计卡片数据 | GET | `/dashboard/summary` | 返回4个核心指标 |
| 获取订单趋势 | GET | `/dashboard/order-trend?days=7` | 折线图数据 |
| 获取订单类型分布 | GET | `/dashboard/order-type-distribution` | 饼图数据 |
| 获取订单状态分布 | GET | `/dashboard/order-status-distribution` | 柱状图数据 |
| 获取待处理事项 | GET | `/dashboard/pending-items` | 待处理计数 |
| 获取关键指标 | GET | `/dashboard/kpi` | 完成率等 |

### 业务规则

1. 数据看板页面自动刷新，建议间隔60秒
2. 财务人员仅可见交易额、结算、提现相关数据，不可见运营指标
3. 时间范围默认为"今日"，支持切换7天/30天
4. 所有金额类数据后端返回分为单位，前端转换为元展示

### 验收要点

- [ ] 4个统计卡片数据正确，支持同期对比
- [ ] 折线图支持7天/30天切换，数据准确
- [ ] 饼图正确展示订单类型占比
- [ ] 待处理事项点击可跳转到对应页面
- [ ] 不同角色看到的数据范围不同
- [ ] 页面支持自动刷新

## AD-02 用户管理

### 基本信息

| 属性 | 值 |
|------|-----|
| 页面编号 | AD-02 |

### 页面目标

| nickname | 昵称 | string | 是(模糊) | 否 | 文本 |
| avatar | 头像 | string | 否 | 否 | 缩略图(32x32) |

| order_count | 订单数 | number | 否 | 是 | 文本 |
| total_amount | 累计消费 | number | 否 | 是 | ¥xxx.xx |
| created_at | 注册时间 | datetime | 是(日期范围) | 是 | YYYY-MM-DD HH:mm:ss |
| last_login_at | 最后登录 | datetime | 否 | 是 | YYYY-MM-DD HH:mm:ss |

### 搜索区字段

| 字段 | 控件类型 | 说明 |
|------|----------|------|
| 用户ID | El-Input(数字) | 精确匹配 |
| 手机号 | El-Input | 精确匹配 |
| 昵称 | El-Input | 模糊搜索 |
| 账号状态 | El-Select | 全部/正常/冻结/注销 |
| 黑名单 | El-Select | 全部/是/否 |
| 注册时间 | El-DatePicker(范围) | 开始-结束日期 |

### 操作按钮与权限

| 按钮 | 位置 | 权限标识 | 可用角色 | 说明 |
|------|------|----------|----------|------|
| 导出 | 操作区 | `user:export` | 超级管理员 | 导出用户列表Excel |
| 查看详情 | 行操作 | `user:detail` | 超级管理员、客服人员 | 打开详情弹窗 |
| 冻结 | 行操作 | `user:freeze` | 超级管理员 | 状态为"正常"时可用 |
| 解冻 | 行操作 | `user:unfreeze` | 超级管理员 | 状态为"冻结"时可用 |
| 加入黑名单 | 行操作 | `user:blacklist:add` | 超级管理员 | 非黑名单用户可用 |
| 移出黑名单 | 行操作 | `user:blacklist:remove` | 超级管理员 | 黑名单用户可用 |

### 详情弹窗（El-Drawer）

| 区域 | 展示内容 |
|------|----------|
| 基本信息 | 头像、昵称、手机号、注册时间、最后登录、账号状态、黑名单状态 |
| 地址列表 | 用户所有收货地址，仅查看 |
| 订单统计 | 总订单数、商品订单数、跑腿订单数、总消费金额 |
| 最近订单 | 最近10条订单列表（订单号、类型、金额、状态、时间），点击跳转AD-07 |
| 优惠券 | 持有优惠券列表（券名、面额、状态、有效期） |
| 投诉记录 | 发起的投诉列表（工单号、类型、状态），点击跳转AD-10 |

### 冻结/解冻表单

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| 操作原因 | El-Input(textarea) | 是 | 最少10字 | 冻结/解冻原因 |

### 依赖后端接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 用户列表 | GET | `/users` | 分页+筛选 |
| 用户详情 | GET | `/users/{id}` | 基本信息 |
| 用户订单统计 | GET | `/users/{id}/order-stats` | 订单统计 |
| 用户最近订单 | GET | `/users/{id}/recent-orders` | 最近订单 |
| 用户优惠券 | GET | `/users/{id}/coupons` | 优惠券列表 |
| 冻结用户 | PUT | `/users/{id}/freeze` | body: { reason } |
| 解冻用户 | PUT | `/users/{id}/unfreeze` | body: { reason } |
| 加入黑名单 | PUT | `/users/{id}/blacklist/add` | body: { reason } |
| 移出黑名单 | PUT | `/users/{id}/blacklist/remove` | body: { reason } |
| 导出用户 | GET | `/users/export` | 返回文件流 |

### 业务规则

1. 冻结用户后，该用户无法登录和下单，已有进行中订单不受影响
2. 黑名单用户同时处于冻结状态
3. 客服人员只能查看用户信息，不能执行冻结/黑名单操作
4. 手机号脱敏展示，超级管理员点击可查看完整号码
5. 冻结/解冻操作必须填写原因，且自动记录审计日志

### 验收要点

- [ ] 用户列表支持多条件搜索和分页
- [ ] 详情弹窗展示完整用户信息
- [ ] 冻结/解冻功能正确，状态实时更新
- [ ] 黑名单加入/移出功能正确
- [ ] 客服人员无法执行冻结/黑名单操作
- [ ] 手机号脱敏展示
- [ ] 导出Excel文件可打开且数据正确

| 审核驳回 | 行操作 | `merchant:audit:reject` | 超级管理员、审核人员 | 审核状态为"待审核"时可用 |

| 审核记录 | 审核时间线（提交→审核→通过/驳回，含操作人和原因） |

### 审核表单

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| 审核结果 | El-Radio | 是 | 必选 | 通过/驳回 |
| 驳回原因 | El-Input(textarea) | 驳回时必填 | 最少10字 | 驳回时说明原因 |
| 审核备注 | El-Input(textarea) | 否 | 最多200字 | 内部备注 |

### 依赖后端接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 商家列表 | GET | `/merchants` | 分页+筛选 |
| 商家详情 | GET | `/merchants/{id}` | 含门店列表 |
| 商家经营数据 | GET | `/merchants/{id}/stats` | 统计数据 |
| 商家结算信息 | GET | `/merchants/{id}/settlement` | 结算数据 |
| 商家审核记录 | GET | `/merchants/{id}/audit-logs` | 审核时间线 |
| 审核通过 | PUT | `/merchants/{id}/audit/approve` | body: { remark } |
| 审核驳回 | PUT | `/merchants/{id}/audit/reject` | body: { reason, remark } |
| 封禁商家 | PUT | `/merchants/{id}/ban` | body: { reason } |
| 解封商家 | PUT | `/merchants/{id}/unban` | body: { reason } |
| 导出商家 | GET | `/merchants/export` | 返回文件流 |

### 业务规则

1. 审核人员只能执行审核操作（通过/驳回），不能封禁/解封
2. 审核通过后，商家端APP中审核状态更新为"已通过"，商家可开始经营
3. 审核驳回后，商家可在APP端查看驳回原因并重新提交
4. 封禁商家后，其所有门店自动下线，已有进行中订单需人工处理
5. 营业执照图片支持点击放大查看
6. 审核操作自动记录审计日志

### 验收要点

- [ ] 商家列表支持多条件搜索
- [ ] 审核通过/驳回功能正确
- [ ] 封禁/解封功能正确且联动门店状态
- [ ] 详情页Tab切换展示完整信息
- [ ] 审核人员只能审核，不能封禁
- [ ] 营业执照图片可放大查看
