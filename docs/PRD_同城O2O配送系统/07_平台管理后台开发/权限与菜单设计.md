### 1.2 菜单数据结构

每个菜单节点的数据结构定义：

```typescript
interface MenuItem {
  id: number;
  parentId: number | null;      // null 表示一级菜单
  name: string;                  // 菜单名称
  code: string;                  // 菜单编码（权限标识前缀）
  path: string;                  // 路由路径
  icon: string;                  // 图标名称（Element Plus Icon）
  sort: number;                  // 排序值
  type: 'directory' | 'page';   // directory=目录, page=页面
  visible: boolean;              // 是否在侧边栏显示
  component: string;             // 页面组件路径
}
```

## 三、数据权限设计

### 3.1 数据权限级别

| 级别 | 说明 | 适用场景 |
|------|------|----------|
| 全平台 | 可访问所有数据 | 超级管理员 |
| 按职能范围 | 只可访问职能相关的数据类型 | 运营/审核/客服/财务 |
| 按操作对象 | 只可操作自己负责的工单/订单 | 客服人员处理中的工单 |

### 3.2 各角色数据权限规则

| 角色 | 数据权限规则 |
|------|-------------|
| 超级管理员 | 无限制，可查看和操作全平台所有数据 |
| 运营人员 | 可查看运营相关数据（商品、活动、配置），不可查看用户隐私、财务明细、审计日志 |
| 审核人员 | 可查看待审核的商家/骑手数据，可查看商品巡检数据，不可查看订单/财务/系统数据 |
| 客服人员 | 可查看订单数据（脱敏手机号），可操作售后/异常/投诉，不可查看商家财务/系统配置 |
| 财务人员 | 可查看结算/提现/退款相关数据，可查看数据看板中的财务指标，不可查看其他管理数据 |

### 3.3 敏感数据脱敏规则

| 数据类型 | 脱敏规则 | 可查看完整数据的角色 |
|----------|----------|---------------------|
| 用户手机号 | `138****1234` | 超级管理员（点击查看） |
| 骑手手机号 | `138****1234` | 超级管理员（点击查看） |
| 身份证号 | `110***********1234` | 超级管理员、审核人员（审核时） |
| 银行卡号 | `****1234` | 超级管理员、财务人员 |
| API密钥 | `sk-****abcd` | 超级管理员（编辑模式） |

## 四、RBAC实现方案

### 4.1 数据模型

```
┌─────────┐     ┌──────────┐     ┌──────────────┐
│ admins  │────>│  roles   │────>│ permissions  │
│ 管理员表 │ N:1 │ 角色表    │ N:N │ 权限点表      │
└─────────┘     └──────────┘     └──────────────┘
                      │
                      │ N:N
                      ▼
                ┌──────────┐
                │  menus   │
                │ 菜单表    │
                └──────────┘
```

### 4.2 数据表结构

**admins（管理员表）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT PK AUTO_INCREMENT | 管理员ID |
| username | VARCHAR(50) UNIQUE | 登录账号 |
| password_hash | VARCHAR(255) | 密码哈希(bcrypt) |
| real_name | VARCHAR(50) | 真实姓名 |
| phone | VARCHAR(20) | 手机号 |
| role_id | INT FK | 角色ID |
| status | TINYINT | 1=启用, 0=禁用 |
| last_login_at | DATETIME | 最后登录时间 |
| last_login_ip | VARCHAR(50) | 最后登录IP |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

**roles（角色表）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT PK AUTO_INCREMENT | 角色ID |
| name | VARCHAR(50) UNIQUE | 角色名称 |
| code | VARCHAR(50) UNIQUE | 角色编码 |
| description | VARCHAR(200) | 角色描述 |
| is_system | TINYINT | 1=系统角色(不可删改), 0=自定义 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

**permissions（权限点表）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT PK AUTO_INCREMENT | 权限ID |
| name | VARCHAR(100) | 权限名称 |
| code | VARCHAR(100) UNIQUE | 权限编码(如 `user:freeze`) |
| type | ENUM('menu','button') | menu=菜单权限, button=操作权限 |
| parent_id | INT | 父权限ID |
| sort | INT | 排序值 |

**role_permissions（角色-权限关联表）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| role_id | INT FK | 角色ID |
| permission_id | INT FK | 权限ID |
| 联合主键 | (role_id, permission_id) | - |

### 4.3 权限编码规范

权限编码采用 `资源:操作` 的命名规范：

```
user:list          - 查看用户列表
user:detail        - 查看用户详情
user:freeze        - 冻结用户
user:unfreeze      - 解冻用户
user:blacklist:add - 加入黑名单
user:export        - 导出用户

merchant:list      - 查看商家列表
merchant:detail    - 查看商家详情
merchant:audit:approve - 审核通过商家
merchant:audit:reject  - 审核驳回商家
merchant:ban       - 封禁商家
merchant:export    - 导出商家

order:list         - 查看订单列表
order:detail       - 查看订单详情
order:assign-rider - 手动指派骑手
order:force-close  - 强制关闭订单
order:refund       - 发起退款
order:remark       - 添加备注
order:export       - 导出订单

...（其余权限编码参见功能模块开发任务.md中各页面的权限标识定义）
```

### 4.4 登录与Token流程

```
1. 管理员提交 username + password
2. 后端验证凭证，查询角色和权限
3. 生成JWT Token，payload包含:
   {
     adminId: number,
     username: string,
     roleId: number,
     roleCode: string,
     permissions: string[]   // 权限编码数组
   }
4. 返回Token + 管理员信息 + 菜单列表 + 权限列表
5. 前端存储Token到内存（不存localStorage防XSS）
6. 前端存储菜单和权限到Pinia Store
7. Token过期时间建议: 2小时，支持刷新Token
```

### 5.2 路由守卫逻辑

```typescript
// router/guard.ts
// 在 art-design-pro 已有的路由守卫（guards）基础上扩展
router.beforeEach(async (to, from, next) => {
  const userStore = useUserStore();
  const permissionStore = usePermissionStore();

  // 1. 登录页直接放行
  if (to.path === '/login') {
    return next();
  }

  // 2. 检查Token是否存在
  if (!userStore.token) {
    return next(`/login?redirect=${to.path}`);
  }

  // 3. 检查是否已加载用户信息和菜单
  if (!userStore.userInfo) {
    try {
      await userStore.getUserInfo();
      const accessRoutes = permissionStore.generateRoutes(userStore.permissions);
      accessRoutes.forEach(route => router.addRoute(route));
      return next({ ...to, replace: true });
    } catch (error) {
      userStore.logout();
      return next(`/login?redirect=${to.path}`);
    }
  }

  // 4. 检查页面权限
  if (to.meta.permission && !permissionStore.hasPermission(to.meta.permission as string)) {
    return next('/404');
  }

  next();
});
```

### 5.3 权限Store设计

```typescript
// stores/permission.ts
// 使用 Pinia 3 进行状态管理，扩展 art-design-pro 已有的权限封装
import { defineStore } from 'pinia';

export const usePermissionStore = defineStore('permission', {
  state: () => ({
    permissions: [] as string[],    // 当前用户的权限编码列表
    menuList: [] as MenuItem[],     // 当前用户可见的菜单列表
    routes: [] as RouteRecordRaw[], // 当前用户可访问的路由
  }),

  actions: {
    setPermissions(permissions: string[]) {
      this.permissions = permissions;
    },

    hasPermission(permission: string): boolean {
      return this.permissions.includes(permission) || this.permissions.includes('*');
    },

    generateRoutes(permissions: string[]): RouteRecordRaw[] {
      // 根据权限过滤动态路由
      this.routes = filterRoutesByPermission(asyncRoutes, permissions);
      return this.routes;
    },
  },
});
```

## 六、按钮级权限控制方案

### 6.1 自定义指令方案

```typescript
// directives/permission.ts
import type { Directive } from 'vue';
import { usePermissionStore } from '@/stores/permission';

export const vPermission: Directive<HTMLElement, string | string[]> = {
  mounted(el, binding) {
    const permissionStore = usePermissionStore();
    const requiredPermissions = Array.isArray(binding.value) 
      ? binding.value 
      : [binding.value];
    
    const hasPermission = requiredPermissions.some(p => 
      permissionStore.hasPermission(p)
    );

    if (!hasPermission) {
      el.parentNode?.removeChild(el);
    }
  },
};

// 全局注册
app.directive('permission', vPermission);
```

```typescript
// composables/usePermission.ts
import { usePermissionStore } from '@/stores/permission';

export function usePermission() {
  const store = usePermissionStore();

  function hasPermission(permission: string | string[]): boolean {
    const perms = Array.isArray(permission) ? permission : [permission];
    return perms.some(p => store.hasPermission(p));
  }

  return { hasPermission };
}

// 在组件中使用
const { hasPermission } = usePermission();
const canFreeze = computed(() => hasPermission('user:freeze'));
```

## 九、安全注意事项

1. **Token安全**：JWT Token存储在内存中（Pinia Store），页面刷新后通过refreshToken重新获取，避免XSS攻击
2. **接口鉴权**：所有后端接口必须校验Token和权限，前端权限控制仅用于UI展示优化，不可作为安全边界
3. **密码策略**：密码最少8位，包含字母和数字，后端使用bcrypt哈希存储
4. **登录安全**：连续5次密码错误锁定账号30分钟，记录登录IP
5. **操作审计**：所有敏感操作记录审计日志，包含操作人、时间、IP、操作前后数据
6. **会话管理**：Token有效期2小时，支持刷新；单点登录（同一账号只允许一处登录）
