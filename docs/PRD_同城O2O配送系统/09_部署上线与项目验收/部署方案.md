## 一、服务器环境要求

### 1.1 最低配置（首期推荐）

|-----------|------|-----|------|------|------|------|

| 数据库服务器 | 1台 | 4核 | 8GB | 200GB SSD | 内网 | MySQL 8.0 + Redis 7.0 |

## 三、部署步骤

### 3.1 基础环境准备

```bash
# 1. 更新系统
sudo apt update && sudo apt upgrade -y

# 2. 安装Node.js 20.x（管理后台要求 >= 20.19.0）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v  # 验证版本

# 3. 安装PM2
sudo npm install -g pm2
pm2 -v  # 验证版本

# 4. 安装Nginx
sudo apt install -y nginx
sudo systemctl enable nginx

# 5. 安装Git
sudo apt install -y git

# 6. 创建部署用户和目录
sudo useradd -m -s /bin/bash deploy
sudo mkdir -p /var/www/o2o-api
sudo mkdir -p /var/www/o2o-admin
sudo mkdir -p /var/log/o2o
sudo chown -R deploy:deploy /var/www/o2o-api
sudo chown -R deploy:deploy /var/www/o2o-admin
sudo chown -R deploy:deploy /var/log/o2o
```

### 3.2 MySQL 8.0 部署

```bash
# 1. 安装MySQL
sudo apt install -y mysql-server

# 2. 安全初始化
sudo mysql_secure_installation
# 设置root密码、移除匿名用户、禁止远程root登录、删除test库

# 3. 创建应用数据库和用户
sudo mysql -u root -p
```

```sql
-- 创建数据库
CREATE DATABASE o2o_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 创建应用用户（仅允许应用服务器IP连接）
CREATE USER 'o2o_app'@'应用服务器IP' IDENTIFIED BY '强密码（至少16位，含大小写字母数字特殊字符）';
GRANT SELECT, INSERT, UPDATE, DELETE ON o2o_prod.* TO 'o2o_app'@'应用服务器IP';
FLUSH PRIVILEGES;

-- 创建只读用户（用于数据导出和统计）
CREATE USER 'o2o_readonly'@'应用服务器IP' IDENTIFIED BY '另一个强密码';
GRANT SELECT ON o2o_prod.* TO 'o2o_readonly'@'应用服务器IP';
FLUSH PRIVILEGES;
```

```bash
# 4. 优化MySQL配置
sudo vim /etc/mysql/mysql.conf.d/mysqld.cnf
```

```ini
# /etc/mysql/mysql.conf.d/mysqld.cnf 关键配置
[mysqld]
bind-address = 数据库服务器内网IP
port = 3306
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
max_connections = 200
innodb_buffer_pool_size = 4G
innodb_log_file_size = 256M
innodb_flush_log_at_trx_commit = 1
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 2
```

```bash
# 5. 重启MySQL
sudo systemctl restart mysql

# 6. 导入数据库结构
mysql -u o2o_app -p o2o_prod < /path/to/schema.sql

# 7. 导入初始化数据（角色、权限、管理员、配置项等）
mysql -u o2o_app -p o2o_prod < /path/to/init_data.sql
```

### 3.3 Redis 7.0 部署

```bash
# 1. 安装Redis
sudo apt install -y redis-server

# 2. 配置Redis
sudo vim /etc/redis/redis.conf
```

```ini
# /etc/redis/redis.conf 关键配置
bind 数据库服务器内网IP
port 6379
requirepass Redis强密码
maxmemory 2gb
maxmemory-policy allkeys-lru
save 900 1
save 300 10
save 60 10000
appendonly yes
appendfsync everysec
```

```bash
# 3. 重启Redis
sudo systemctl restart redis-server
sudo systemctl enable redis-server

# 4. 验证连接
redis-cli -h 数据库服务器内网IP -a Redis强密码 ping
# 应返回PONG
```

### 3.4 后端服务部署

```bash
# 1. 切换到部署用户
sudo su - deploy

# 2. 克隆代码
cd /var/www/o2o-api
git clone 代码仓库地址 .
git checkout release/v1.0

# 3. 安装依赖
npm ci --production

# 4. 创建环境变量文件
cp .env.example .env
vim .env  # 编辑配置（见下方环境变量清单）

# 5. 编译TypeScript
npm run build

# 6. 数据库迁移（如有）
npm run migrate

# 7. 使用PM2启动服务
pm2 start ecosystem.config.js --env production

# 8. 保存PM2进程列表并设置开机自启
pm2 save
pm2 startup
```

### 3.5 管理后台前端部署

```bash

### 3.6 用户微信端（H5页面）部署

用户微信端为基于微信公众号入口的H5页面，作为轻量级入口提供订单查询、骑手追踪等功能。

```bash
# 1. 在开发机或CI环境构建H5版本
cd o2o-h5-frontend
npm ci
npm run build:h5  # 产出 dist/h5/ 目录

# 2. 上传构建产物到服务器
sudo mkdir -p /var/www/o2o-h5
sudo chown -R deploy:deploy /var/www/o2o-h5
scp -r dist/h5/* deploy@应用服务器IP:/var/www/o2o-h5/

# 或使用rsync
rsync -avz --delete dist/h5/ deploy@应用服务器IP:/var/www/o2o-h5/
```

#### 微信公众号配置

| 配置项 | 说明 | 操作位置 |
|--------|------|----------|
| JS接口安全域名 | 填写H5页面域名（如 `h5.example.com`） | 公众号设置 → 功能设置 |
| 网页授权域名 | 同上，用于微信OAuth登录 | 公众号设置 → 功能设置 |
| 业务域名 | 同上，避免跳转提示 | 公众号设置 → 功能设置 |
| 自定义菜单 | 配置公众号底部菜单，链接到H5页面 | 自定义菜单 |
| 模板消息 | 配置订单状态变更通知模板 | 添加功能插件 → 模板消息 |

#### 注意事项

- H5页面需通过微信OAuth2.0获取用户身份（openid），后端需实现 `/api/v1/auth/wechat-h5-login` 接口
- JS-SDK签名接口需后端提供 `/api/v1/wechat/jsapi-signature`，用于调起微信支付和分享
- 必须在微信支付商户平台配置H5支付域名（如需H5端支付）
- 验证文件：微信公众平台要求将验证文件放置在域名根目录下，需部署到 `/var/www/o2o-h5/` 目录

### 3.7 Nginx配置

```bash
sudo vim /etc/nginx/sites-available/o2o.conf
```

```nginx
# /etc/nginx/sites-available/o2o.conf

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name api.example.com admin.example.com h5.example.com;
    return 301 https://$server_name$request_uri;
}

# API服务
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate /etc/ssl/certs/example.com.pem;
    ssl_certificate_key /etc/ssl/private/example.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # API代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;

        # 文件上传大小限制
        client_max_body_size 10m;
    }

    # WebSocket支持（用于实时推送）
    location /ws/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # 支付回调（不限流）
    location /api/payment/callback {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

# 管理后台
server {
    listen 443 ssl http2;
    server_name admin.example.com;

    ssl_certificate /etc/ssl/certs/example.com.pem;
    ssl_certificate_key /etc/ssl/private/example.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    root /var/www/o2o-admin;
    index index.html;

    # SPA路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # API代理（管理后台的API请求）
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

# 用户微信端H5页面

## 七、小程序审核发布流程

```
1. 开发者工具上传代码
   → 微信开发者工具 → 上传 → 填写版本号和备注

2. 提交审核
   → 微信公众平台 → 版本管理 → 提交审核
   → 填写功能说明、测试账号
   → 上传功能截图

3. 等待审核（通常1-3个工作日）
   → 审核通过则可发布
   → 审核不通过需修改后重新提交

4. 正式发布
   → 审核通过后 → 全量发布

注意事项：
- 小程序需配置合法域名（在公众平台配置request域名）
- 涉及支付的需要在小程序后台关联支付商户号
- 分享功能需要配置分享页面路径
- 首次提交建议准备完整的资质材料
```

### 8.1 Android上架

| 应用市场 | 所需材料 | 审核周期 | 说明 |
|----------|----------|----------|------|
| 华为应用市场 | APK/AAB、应用截图、隐私政策、资质文件 | 1-3天 | 需实名认证 |
| 小米应用商店 | 同上 | 1-2天 | 需开发者账号 |
| OPPO软件商店 | 同上 | 1-2天 | 需开发者认证 |
| VIVO应用商店 | 同上 | 1-2天 | 需企业认证 |

```
通用上架步骤：
1. 注册开发者账号并完成企业认证
2. 创建应用，填写应用信息（名称、描述、分类、图标）
3. 上传APK/AAB安装包
4. 上传应用截图（至少3张，建议5张）
5. 填写版权证明和资质文件
6. 填写隐私政策URL
7. 填写测试账号
8. 提交审核
```

### 8.2 iOS上架

```
1. Apple Developer账号
   → 需要Apple Developer Program会员（企业或个人）
   → 年费99美元

2. 准备材料
   → App图标（1024x1024）
   → 截图（iPhone各尺寸）
   → 应用描述、关键词、隐私政策URL

3. Xcode归档上传
   → Xcode → Product → Archive → Upload to App Store Connect

4. App Store Connect配置
   → 填写App信息
   → 选择构建版本
   → 配置定价（免费）
   → 提交审核

5. 审核周期：通常3-7个工作日
   → 首次提交审核较严格
   → 审核不通过需根据反馈修改

注意事项：
- iOS审核较严格，需确保不使用私有API
- 需要在Info.plist中说明所有权限用途（定位、相机、通知等）
- uni-app x 打包iOS需要Apple证书和Provisioning Profile
```

## 十、数据备份策略

### 10.1 MySQL备份

```bash
# 每日全量备份脚本
#!/bin/bash
BACKUP_DIR="/backup/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
mysqldump -u o2o_readonly -p密码 o2o_prod | gzip > $BACKUP_DIR/o2o_prod_$DATE.sql.gz

# 保留最近30天备份
find $BACKUP_DIR -name "*.sql.gz" -mtime +30 -delete

# 配置crontab每日凌晨3点执行
# 0 3 * * * /path/to/backup_mysql.sh
```

### 10.2 Redis备份

```bash
# Redis RDB自动备份（已在redis.conf中配置）
# 备份RDB文件到远程
#!/bin/bash
BACKUP_DIR="/backup/redis"
DATE=$(date +%Y%m%d_%H%M%S)
cp /var/lib/redis/dump.rdb $BACKUP_DIR/dump_$DATE.rdb

# 保留最近7天
find $BACKUP_DIR -name "*.rdb" -mtime +7 -delete
```

### 10.3 文件备份

```bash
# 上传文件备份
#!/bin/bash
BACKUP_DIR="/backup/uploads"

tar -czf $BACKUP_DIR/uploads_$DATE.tar.gz /var/www/o2o-api/uploads/

# 保留最近7天
find $BACKUP_DIR -name "*.tar.gz" -mtime +7 -delete
```

## 十一、回滚方案

### 11.1 后端服务回滚

```bash
# 1. 使用Git回滚到上一个版本
cd /var/www/o2o-api
git log --oneline -5  # 查看最近5个版本
git checkout 上一个版本的commit-hash

# 2. 重新安装依赖和构建
npm ci --production
npm run build

# 3. 重启PM2
pm2 restart o2o-api

# 4. 验证服务正常
curl http://localhost:3000/api/health
```

### 11.2 前端回滚

```bash
# 备份当前版本
cp -r /var/www/o2o-admin /var/www/o2o-admin.bak.$(date +%Y%m%d)

# 恢复上一版本
cp -r /var/www/o2o-admin.上次备份日期/* /var/www/o2o-admin/

# Nginx不需要重启（静态文件直接生效）
```

### 11.3 数据库回滚

```bash
# 恢复最近的数据库备份
gunzip < /backup/mysql/o2o_prod_最近日期.sql.gz | mysql -u root -p o2o_prod

# 注意：数据库回滚需要停服操作，需在维护窗口执行
```
